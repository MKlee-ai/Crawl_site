## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | 픽셀 방치형 RPG (자동 전투 + 성장 + 무기 빌드) |
| 화면 | 세로(Portrait) 고정, 한 손 조작 |
| 진행 | 종(세로) 스크롤 — 탑을 **위로** 오름 |
| 플랫폼 | Android (Google Play) |
| 핵심 재미 | ① 들어올 때마다 쌓여 있는 성장 ② **무기·스탯 조합 연구** ③ 다음 층 이야기에 대한 궁금증 |

**한 줄 정의**
역병에 걸린 동생을 살리기 위해, 몰락한 기사 가문의 검사가 하늘에 닿은 종탑을 오른다. 쓰러질 때마다 종이 울리고 시간은 되돌아가지만, 검을 쥔 손의 기억은 남는다.

## 2. 세계관 & 스토리

### 2.1 배경
- **알베른 왕국**: 가상의 중세 유럽풍 왕국. 성채와 수도원, 자유도시, 기사단이 있는 세계.
- **잿빛 역병**: 몇 년 전부터 번진 역병. 걸리면 피부가 잿빛 돌처럼 굳어간다.
- **성 아르멜의 종탑**: 하룻밤 사이에 왕국 한가운데 솟아오른 끝이 보이지 않는 탑. 교회는 "꼭대기의 종을 울리는 자는 모든 역병을 거둘 수 있다"고 설교한다. 수많은 기사가 올라갔지만 돌아온 이는 없다.

### 2.2 등장인물

| 인물 | 역할 | 설명 |
|---|---|---|
| **카엘** (이름 변경 가능) | 주인공 / 검사 | 몰락한 기사 가문의 막내. 정식 기사 서임을 받지 못한 떠돌이 검사. 동생을 구하려고 탑에 오른다. |
| **엘라** | 동생 | 잿빛 역병 환자. 오빠에게 편지를 남긴다 (기록 조각 = 엘라의 편지). |
| **가레스** | 동료 1 / 멘토 | 탑 1장에서 만나는 **해골 기사**. 말이 많고 능청스러움. 무기 다루는 법을 가르쳐 주는 튜토리얼 담당. *정체가 핵심 반전.* |
| **마리엔** | 동료 2 / 회복 | 2장 지하묘지에서 합류하는 견습 수녀이자 연금술사. 교회의 비밀을 조금씩 알게 된다. |
| **발드릭** | 최종 보스 | 성기사단장. 종을 지키는 자. "종에는 대가가 필요하다"고 믿는다. |

### 2.3 회귀(환생) 설정
- 탑에서 쓰러지거나 스스로 "종의 맹세"를 하면 **종이 울리고 시간이 탑에 처음 들어온 날로 되돌아간다**.
- 레벨·장비는 사라지지만 **검의 기억(영구 재화 「각인」)**은 남는다 → 프레스티지 시스템.
- 회귀를 거듭할수록 NPC 대사가 미묘하게 달라짐 (회귀 횟수에 따른 대사 분기) → 회귀 자체가 스토리 콘텐츠.

### 2.4 챕터 구성 (1장 = 50층, 10층마다 보스)

| 장 | 층 | 지역 | 주요 적 (방어 타입) | 해금 무기 | 스토리 비트 |
|---|---|---|---|---|---|
| 프롤로그 | - | 고향 마을 | - | 평도 | 엘라의 발병, 탑으로 출발 |
| 1장 | 1–50 | 무너진 성채 | 도적·들개 (경갑) | **평도** (시작) | 해골 기사 가레스와 만남. 보스: 녹슨 성문지기 |
| 2장 | 51–100 | 성 아르멜 지하묘지 | 해골·구울 (언데드) | **둔기** (전투 수도사의 메이스) | 마리엔 합류. 종의 전설에 숨겨진 의문 |
| 3장 | 101–150 | 용병 자유도시 | 사슬갑옷 용병 | **세검** (결투사 로셀의 레이피어) | 탑 안에 "시대가 다른 도시"가 있다는 사실 |
| 4장 | 151–200 | 철의 요새 | 판금 기사단 | **대검** (용병대장의 츠바이핸더) | **첫 번째 반전**: 탑에 갇힌 기사들은 모두 회귀 중이었다 |
| 5장 | 201–250 | 마녀의 숲 | 영체·정령 | **마단검** (마녀가 남긴 단검) | 역병의 기원은 탑. **두 번째 반전**: 가레스는 수백 번 회귀한 미래의 카엘 |
| 6장 | 251–300 | 구름 위 대성당 | 성기사·악마 | **마검** (발드릭의 검과 쌍을 이루는 검) | 종의 진실: 종은 회귀자들의 영혼으로 울린다. 최종 결전 |
| 엔드 | 301+ | 무한 종루 | 혼합 | - | 엔딩 이후 무한 층 (랭킹·도전 콘텐츠) |

- 챕터의 적 방어 타입과 그 챕터에서 해금되는 무기가 맞물리도록 설계 → **스토리 진행 = 새 무기 = 새 빌드**.
- 엔딩 분기(종을 울린다 / 종을 부순다)는 v1.0 이후 검토.

### 2.5 스토리 전달 방식 (세로 화면용)
- **보스 클리어 → 메인 스토리 1화**: 세로 웹툰식 도트 컷 3~6장 + 대사창
- **기록 조각**: 일반 층에서 낮은 확률로 "엘라의 편지 / 기사들의 일지" 드롭 → 도감에서 열람
- **모닥불 대화**: 대기 화면에서 가레스·마리엔의 짧은 대화 (회귀 횟수·장착 무기에 따라 달라짐)
- **복귀 요약**: 오프라인 보상 팝업에 "그동안 가레스가 한 말" 한 줄

## 4. 코어 루프

```
자동 전투 → 골드/경험치/무기 드롭 → 레벨업(스탯 포인트) → 스탯 분배 & 무기 선택
   ↑                                                       ↓
오프라인 보상 ← 종료 ← 보스에서 막힘 ← 층 돌파 → 스토리/새 무기 해금
                                         ↓
                          회귀(프레스티지) → 각인으로 영구 강화
```

| 루프 | 주기 | 내용 |
|---|---|---|
| 마이크로 | 수 초 | 자동 공격, 스킬, 드롭 |
| 세션 | 2~3분 | 오프라인 보상 → 스탯/무기 조정 → 보스 도전 → 스토리 |
| 데일리 | 1일 | 일일 의뢰, 무기 숙련 던전, 출석 |
| 메타 | 1~2주 | 회귀, 새 챕터, 새 무기 빌드 |

## 6. 픽셀 아트 사양

| 항목 | 사양 |
|---|---|
| 논리 해상도 | **가로 180px 고정**, 세로 320~400px (기기 비율에 따라 위아래 배경 확장) |
| 확대 방식 | 정수 배율 (1080px 폭 기기 → ×6), 최근접 이웃(nearest) 보간 — 픽셀 뭉개짐 방지 |
| 캐릭터 | 32×32 (주인공·일반 적), 보스 64×64 ~ 96×96 |
| 타일/배경 | 16×16 타일 + 세로로 반복되는 패럴랙스 배경 (챕터당 3레이어) |
| 팔레트 | 32색 제한 공용 팔레트 (예: Endesga 32 계열) → 전체 톤 통일 |
| 주인공 스프라이트 | **몸통 + 무기 레이어 분리** → 무기를 바꾸면 외형도 바뀜 |
| 공격 모션 | 피해 타입 기준 **3세트 공유**: 찌르기(세검·마단검) / 베기(평도·마검) / 휘두르기(대검·둔기) → 작업량 절감 |
| 마력 표현 | 마단검·마검은 모션 공유 + 마력 이펙트 레이어 추가 |
| 한글 폰트 | 픽셀 한글 폰트 (예: 갈무리 Galmuri, OFL 라이선스) |
| 제작 툴 | Aseprite (스프라이트시트 + JSON 내보내기) |
| 외부 에셋 | 구매·무료 에셋 사용 시 **상업적 이용 라이선스** 확인 후 사용 |

## 7. 기술 스택 (Android)

| 옵션 | 장점 | 단점 |
|---|---|---|
| **Phaser + TypeScript + Vite + Capacitor** (추천) | 모든 게임 로직이 코드라 Claude Code로 개발·수정이 가장 쉬움. 브라우저에서 바로 테스트 후 Capacitor로 Android APK/AAB 빌드. `pixelArt: true` 옵션으로 도트 렌더링 지원 | 고사양 연출·네이티브 성능은 엔진 대비 약함 (방치형엔 충분) |
| Godot 4 | 2D 픽셀 게임에 강함, 무료, Android 내보내기 내장 | 씬 편집이 에디터 중심 → 코드만으로 작업하기 불편 |
| Unity 2D | 광고·결제 SDK 생태계 최강 | 무겁고 반복 속도 느림, 에디터 의존도 높음 |

**추천 구성**
- 렌더링/게임: Phaser (TypeScript)
- 빌드: Vite → Capacitor → Android (Google Play 내부 테스트 트랙)
- 데이터: 무기·적·층·스토리 대사를 JSON으로 관리 (데이터 주도 설계, 밸런싱 = 데이터 수정)
- 큰 수 처리: 방치형용 big number 라이브러리 (예: break_infinity.js)
- 저장: 로컬 저장(Capacitor Preferences) → 이후 Google Play Games 클라우드 저장
- 광고: AdMob (Capacitor 플러그인) — 보상형 광고만
- 오프라인 보상: 마지막 접속 시각 기준 계산 (시계 조작 방지는 v1.0)

## 8. MVP 범위 (10주)

| 포함 | 제외 (이후) |
|---|---|
| 1~2장 (1~100층, 보스 10종) | 3장 이후 |

| 피해 타입 3종 + 적 방어 타입 3종 (경갑·언데드·사슬) | 마력·영체·판금·마물 |

| 오프라인 보상, 로컬 저장 | 클라우드 저장 |
| 회귀 1단계 | 각인 트리 확장 |

| 주차 | 산출물 |
|---|---|
| 1 | 저장소 세팅, 세로 픽셀 렌더링 + 스크롤 + 자동 전투 프로토타입 |
| 2 | 피해 타입·스탯·방어 타입 계산 로직 + 단위 테스트 |
| 3 | 무기 3종 + 스킬 + 퀵스왑 |
| 4 | 레벨/스탯 UI, 무기 아이템(등급·강화) |
| 5 | 층/적/보스 데이터 테이블 (1~100층) |
| 6 | 오프라인 보상, 저장/로드 |
| 7 | 스토리 뷰어(세로 도트 컷 + 대사창), 1~2장 스토리 |
| 8 | 동료, 회귀 |
| 9 | 밸런싱 (목표: 100층까지 약 5일) |
| 10 | Capacitor Android 빌드 → Google Play 내부 테스트 |

## 9. 저장소 추천

이 저장소(`Crawl_site`)는 `CLAUDE.md`에 크롤링·사이트 전용으로 범위가 정해져 있어서, 게임은 **새 저장소로 분리**하는 걸 추천합니다.

- 저장소 이름 예시: `pixel-idle-rpg` 또는 `ashen-belltower`
- 이 PRD와 [[idle-rpg-combat]]는 새 저장소의 `docs/`로 옮김
- 제안 폴더 구조:

```
pixel-idle-rpg/
├─ CLAUDE.md            # 게임 프로젝트용 작업 원칙
├─ docs/                # PRD, 설계 문서 (옵시디언)
├─ src/
│  ├─ scenes/           # Phaser 씬 (Boot, Battle, Story, UI)
│  ├─ systems/          # 전투 계산, 스탯, 오프라인 보상, 저장
│  ├─ data/             # weapons.json, enemies.json, floors.json, story/*.json
│  └─ ui/
├─ assets/
```
